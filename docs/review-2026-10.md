## 0. 一段话总结 + 结论

**想法：** 这是一个纯前端、可离线使用的羽毛球计分 + 赛事管理 Web App（React 19 + Vite 7，部署在 GitHub Pages：https://noowxela.github.io/BadmintonScore/ ）。它不只是一个“记分板”，而是把业余球局和公司内部赛的整条流程都做了：**Quick Match 单场计分** → **Team Match（团体赛：MS/MD/XD 排兵布阵，拖拽安排场地和时间）** → **Knockout 淘汰赛对阵图（自动轮空、铜牌赛、二维码分享）** → **League（分组循环 + 胜者组/败者组杯赛 + 场地时间表）**。另外还有 **球员名册（别名 / 合并）**、**统计** 和 **JSON 备份/恢复**。所有数据都存在 `localStorage`。内置的“LAKSA BOWL 5.0”示例就是一场真实的内部比赛（9 队，分 A/B 两组）。

**结论：** 想法很好，UI 已经有“体育记分板”的感觉，核心计分在手机上很好用。项目乱，主要有三个原因：
1. 8 月一次提交了 5k+ 行（`aa29079`），AI 工具配置、CodePen 试验 HTML、真实赛事数据和新功能全混在一起。
2. 业务逻辑大量堆在 `App.jsx`（410 行、十几个 handler）和页面组件里，状态靠直接读写 `localStorage` 加 props 层层传递。
3. 有几个真实 bug：联赛小组赛结果不回写、直接打开 `/team-dashboard` 白屏、线上 deep link 和分享链接 404。

**不需要重写。** 按下面的分阶段计划，大约 **3 天**（阶段 A + B）就能修掉 bug 和主要的乱；全部做完（含结构重构）约 **5.5–6 天**。之后就是一个干净、可以持续加功能的项目。

### 4.2 Lint 结果（10 个 error / 1 个 warning）
- `ScoreBoard.jsx:10`：`checkWinner` 还没声明就在 `useEffect` 里用了（react-hooks/immutability）。其实 `winner` 可以直接从分数算出来，不需要 state + effect。
- `ScoreBoard.jsx:4`：`onNavigateHome` 没用到。所以 **`App.jsx` 里的 `handleNavigateHome`（约 35 行）是死代码**，而且它和 `handleMatchComplete` 几乎一模一样。
- `App.jsx:36`：effect 里同步 setState；`App.jsx:51`：依赖数组缺 `location.pathname` 和 `navigate`。
- `MatchScheduler.jsx`：`arrayMove`、`teamMatchDate`、`setNumSlots`、`node` 没用到；effect 里 setState。
- `MatchScheduleCard.jsx:31` 的 `getCategoryColor` 和 `MatchupConfig.jsx:360` 的 `percentage` 没用到。

### 4.3 重复代码
- `App.jsx` 的 `handleMatchComplete` 和 `handleNavigateHome`：算团体赛比分的 15 行是直接复制的。
- `handleKnockoutMatchComplete` 和 `handleFinishTeamMatch`：“找 tournament → 找 event → `applyMatchResult` → `saveKnockoutTournament`” 写了两遍。
- `storage.js`：从比赛里收集球员名字的逻辑在 `saveTeamMatch` 和 `collectNamesFromStorage` 里重复；`p1/player1` 的兼容写法到处都是。
- `id === LAKSA_BOWL_ID ? ensureLaksaBowl50() : getKnockoutTournament(id)` 在 `LeagueDashboard`、`LeagueTimetable`、`KnockoutBracket` 各写了一遍，每个文件里还写了两次。
- 弹窗在 `Home`、`LeagueDashboard`、`KnockoutBracket`、`ShareModal` 里各自手写一套 overlay。

### 4.4 状态管理
- 全局状态是 `App.jsx` 里的 3 个 `useState`，各页面再各自直接读写 `localStorage`，没有单一数据源。React state 和存储很容易不同步（例如 `Home` 每次 render 都去读一次存储）。
- 写 `localStorage` 没有 try/catch，存储满了或者 Safari 隐私模式下会直接抛错。数据也没有 schema 版本迁移（只有 Laksa 示例带了 `version`）。
- ID 用 `Date.now()`，同一毫秒内可能撞；到处要写 `String(t.id) === String(id)`，说明 id 类型不统一。

### 4.5 错误处理 / UX 反馈
- 用了 6 处 `window.alert / confirm / prompt`。
- `TeamMatchDashboard` 没处理 `teamMatch === null`，直接打开就白屏（见 §5）。
- 没有 Error Boundary，任何渲染错误都是整页白屏。

### 4.6 依赖健康
- `npm audit`：**15 个漏洞（11 个 high）**。生产依赖里 **react-router 7.9.6 有 2 个 high**（开放重定向、XSS 等，大多针对 SSR，但也有一个 DoS），`npm audit fix` 可以修。
- `npm outdated`：react 19.2.0→19.3.1、react-router-dom 7.9.6→7.18.4、vite 7.2.4→7.3.7（8.x 已经出了）、lucide-react 0.555→1.59（major）、eslint 10、@vitejs/plugin-react 6。
- 所有依赖都有在用（@dnd-kit 只有 `MatchScheduler` 用）。
- 运行时依赖外部服务：二维码用 `api.qrserver.com`（第三方服务，离线不能用，而且会把链接发给第三方）；字体用 Google Fonts。

### 4.7 Secrets
- 没找到 `.env` 或任何 key。`.opencode/agents/review.md` 只写了模型名，没有凭证。
- ⚠️ 但 `laksaBowl50.js` 和海报里有**真实同事的名字**，仓库和网站都是公开的，需要确认大家是否同意公开。

**运行时错误：**
1. 🔴 **直接访问 `/team-dashboard`（没有进行中的团体赛）会白屏**：`Cannot destructure property 'teamA' of 'a' as it is null`（`TeamMatchDashboard.jsx:7`）。刷新页面或从书签进来都会触发。
2. 🔴 **线上 deep link 404**：`https://noowxela.github.io/BadmintonScore/history` 和 `/league/laksa-bowl-50` 都返回 **HTTP 404**，因为 GitHub Pages 没有 SPA fallback。也就是说，在任何子页面刷新都是 404；**对阵图 “Share” 生成的二维码，分享出去的链接也是 404**。
3. 其他页面没有 console error、没有请求失败，手机上也没有横向溢出。

**UX 问题：**
- dark theme 之后，记分页两边颜色几乎一样（`--color-primary: #ff6b00` vs `--color-accent: #ff8a3d`），手机上很难分清左右两队（见 `mobile-03-scoreboard.png`）。

- `LeagueDashboard` 里那句 “No current matches — group stage is complete…” 是写死的，自建联赛也会显示。
- `TeamMatchDashboard` 里的拖拽排程（Scheduler）每次进来都会重置，排好的不会保存。
- `index.html` 的标题是 `badminton_board`，favicon 还是 Vite logo；没有 PWA manifest，不能“添加到主屏幕”离线用。

## 7. 值得保留的优点 ✅

1. **产品想法完整而且真实**：从单场计分一路做到团体赛 + 小组赛 + 胜/败者组杯赛 + 时间表，正好是业余俱乐部和公司内部赛的真实需求，而且已经用真实比赛（Laksa Bowl）验证过。
2. **赛制引擎是纯函数**：`utils/bracket.js`（自动补到 2 的幂、轮空自动晋级、铜牌赛、`applyMatchResult` 不可变更新）、`utils/league.js`（7 级排名规则的 `computeStandings`）、`utils/timetable.js`。这是项目最有价值的部分，也很适合加单元测试。
3. **球员名册设计得不错**：`normalizePlayerName` + 别名 + 合并 + 按规范名汇总统计，解决了“Alex / alex / Alex W”这种真实痛点。
4. **数据导入导出**：备份格式带 `version`，支持 replace 和 merge 两种模式。
5. **UI 观感**：深色体育记分板主题；手机上用大按钮计分；对阵图有缩放、全屏、二维码分享；League 表格在手机上不会溢出。
6. **CI/CD 已经有了**：push 就部署到 GitHub Pages，dependabot 也开了。

## 11. 功能 / 增强建议（在现有想法上延伸）

1. **完整的羽毛球规则**：三局两胜（也可选单局或 15 分制）、发球方和发球区提示、11 分技术暂停、决胜局 11 分换边提醒；逐分记录可以生成比赛走势图。
2. **PWA + 离线**：加 manifest + service worker，场馆网络差也能用，可以“添加到主屏幕”。
3. **实时分享 / 多设备**：现在数据只在本机，分享出去的链接对方看不到自建的赛事。可以接 Firebase 或 Supabase（你的账号已经连了 Firebase），做一个只读的直播页：观众扫码就能看实时比分和对阵图。
4. **通用联赛向导**：输入队伍数 → 自动分组、生成循环赛、设定晋级规则（前 N 名进胜者组）、自动排时间表（场地数和每场分钟数可配置）。把 Laksa Bowl 写死的逻辑变成谁都能用的模板。
5. **记分大屏 / 裁判模式**：横屏大字体、投屏到 TV，手机当遥控器加分。
6. **球员档案**：头像、ELO/积分排名、搭档胜率、对手交手记录（名册和 stats 已经有基础）。
7. **导出**：对阵图和时间表导出成图片或 PDF；比赛结果一键生成 WhatsApp 分享文字。
8. **本地生成二维码**：用本地库（如 `qrcode`）生成二维码，代替 `api.qrserver.com`，离线可用，也不会把链接发给第三方。
9. **多语言**：中文 / 英文 / 马来文（队名本来就是马来文：Badai、Ribut…）。
10. **云备份**：一键备份到 Google Drive，或者定期提醒导出，免得清缓存丢数据。
